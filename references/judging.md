# 判题方法论：本地跑通 + 暴力对拍

只跑题目示例用例是不可靠的——示例往往覆盖不到隐蔽 bug。
本教练的判题分两步，**第二步不能省**。

## 第一步：本地跑测试

```powershell
python solutions/xxxx_xxx.py
```

`solutions/` 下每题的骨架自带示例 + 边界用例。全绿只是必要条件。

## 第二步：暴力对拍（差分测试）

写一个**朴素到不可能错**的黄金标准解，再用随机小数据对拍几百上千组。

模式（见 `assets/differential_test_template.py`）：

```python
def brute(nums):          # 黄金标准：怎么直接怎么写，哪怕 O(n^3)
    ...

import random
for _ in range(2000):
    nums = [random.randint(-5, 5) for _ in range(random.randint(0, 12))]
    assert solve(nums[:]) == brute(nums), nums
```

### 为什么必须对拍

真实案例（三数之和）：用户写的 a 去重用 `i += 1`，本地 6 个示例用例全绿，
但对拍发现 `[-1,-1,-1,0,1,2,2]` 会收两遍 `(-1,0,1)`。
原因：Python 的 `for i in range(...)` 里改 `i` 无效（range 每轮重新赋值），
且缺 `continue`。这类 bug 靠看代码很难发现，对拍一次就抓住。

### 怎么构造对拍数据

- **范围小**：值域收窄（如 -5..5），长度短（0..12），让重复/边界高频出现
- **专门构造"重复值 + 有解"**：如全零、三连重复、正负混杂
- 字符类题用小字母表（如只取 "ab "）提高碰撞率
- 最后再跑一个 10 万级大输入确认不超时（验证复杂度达标）

### 常见黄金标准写法

| 题型 | 黄金标准 |
|---|---|
| 数组求和/配对 | 多层 for + set 去重 |
| 滑动窗口 | 枚举所有子串逐个验证 |
| DP | 暴力递归（不 memo） |
| 链表/树 | 转列表后暴力处理再比较 |

### 复杂度确认

对拍通过后，口头确认：时间复杂度、空间复杂度、是否原地。
不满足题目要求（如要求 O(1) 空间却开了 O(n) 数组）要指出。
